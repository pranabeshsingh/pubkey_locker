Quick Start

pubkey.locker allows developers and systems to resolve public keys using standard command-line utilities. You can fetch registered keys directly in authorized_keys format or JSON.

curl usage examples
$ curl https://pubkey.locker/api/keys/alice
$ curl https://pubkey.locker/alice.keys

Local Development

Clone the repository and install runtime dependencies with Node.js 20+.

git clone git@github.com:pranabeshsingh/pubkey_locker.git
cd pubkey_locker
npm install
cp .env.example .env
# Edit .env with Oracle Wallet credentials
npm run dev

Environment Variables

All configuration is loaded via environment variables or a local .env file:

Variable Description Example
PORT Application HTTP port (default: 3002) 3002
ORACLE_USER Oracle DB username ADMIN
ORACLE_PASSWORD Database password ••••••••
ORACLE_CONNECT_STRING TNS alias in tnsnames.ora pubkeylocker_tp
ORACLE_WALLET_LOCATION Path to extracted wallet directory /opt/pubkey-locker/wallet
ADMIN_TOKEN Secret token for admin API endpoints secret_token_123

Bundle Specification

Public key bundles are JSON objects containing keys, handle metadata, and ownership proofs. 

{
  "version": 1,
  "handle": "alice",
  "keys": [
    {
      "type": "ssh-ed25519",
      "publicKey": "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGd0+bO44D6kG5Z3f6T2fX9x3B8l4N5q2e6Y8X0w1a2b alice@pubkey.locker",
      "fingerprint": "SHA256:d8k3J7mNp9Q1vX4yZ2w8kL5mN7pQ9rS2tU4vW6xY8zA"
    }
  ],
  "proof": {
    "message": "register alice",
    "signature": "u7P9fX2kL8mN4pQ1rS5tU7vW9xY2zA3bC5dE7fG9hI1jK3lM5nO7pQ9rS1tU3vW5",
    "signedBy": "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGd0+bO44D6kG5Z3f6T2fX9x3B8l4N5q2e6Y8X0w1a2b"
  }
}

API Reference

GET /health

Checks application and Oracle Database connectivity.

curl https://pubkey.locker/health

# Response 200 OK
{"ok": true, "db": true}
POST /api/validate

Performs dry-run JSON schema and proof validation without persisting to the database. 

curl -X POST https://pubkey.locker/api/validate \
  -H "Content-Type: application/json" \
  -d '{"version":1,"handle":"alice",...}'

# Response 200 OK
{"valid": true}
POST /api/keys

Validates and stores a signed key bundle in Oracle Autonomous Database.

curl -X POST https://pubkey.locker/api/keys \
  -H "Content-Type: application/json" \
  -d '{"version":1,"handle":"alice",...}'

# Response 201 Created
{"id": "6a9f73d8-5081-4b11-9a7c-1349f7ba3e12", "handle": "alice"}
GET /api/keys/:handle

Resolves the latest registered bundle for the specified handle.

curl https://pubkey.locker/api/keys/alice

# Response 200 OK
{"version": 1, "handle": "alice", "keys": [...], "proof": {...}}
GET /api/bundles

Lists stored bundles. Protected with X-Admin-Token.

curl https://pubkey.locker/api/bundles?limit=50 \
  -H "X-Admin-Token: your_admin_token"

# Response 200 OK
[{"id": "...", "handle": "alice", "createdAt": "2026-10-20T18:00:00.000Z"}]
DELETE /api/keys/:id

Permanently deletes a stored bundle by UUID. Protected with X-Admin-Token. 

curl -X DELETE https://pubkey.locker/api/keys/6a9f73d8-5081-4b11-9a7c-1349f7ba3e12 \
  -H "X-Admin-Token: your_admin_token"

# Response 204 No Content

OpenSSH Integration

Configure OpenSSH daemon to resolve user keys directly from pubkey.locker using AuthorizedKeysCommand in /etc/ssh/sshd_config: 

# In /etc/ssh/sshd_config
AuthorizedKeysCommand /usr/local/bin/pubkey-resolve %u
AuthorizedKeysCommandUser nobody

Create the resolver script in /usr/local/bin/pubkey-resolve:

#!/bin/sh
set -e
USER="$1"
curl -sSf "https://pubkey.locker/${USER}.keys" || exit 0

Deployment & Systemd

Production runs as a systemd service managed behind Caddy reverse proxy on port 3002: 

# Update and restart service
cd /opt/pubkey-locker
git pull origin master
npm ci --omit=dev
sudo systemctl restart pubkey-locker

# Validate and reload Caddy without restarting
sudo caddy validate --config /etc/caddy/Caddyfile
sudo caddy reload --config /etc/caddy/Caddyfile

Security Model

  • Private Keys: Never uploaded or stored. Private keys remain on client machines.
  • Ownership Verification: Registration requires a signature challenge signed by the key.
  • Admin Endpoints: Authenticated strictly with high-entropy X-Admin-Token.
  • Oracle Cloud Wallet: Excluded from git repositories, stored with restricted permissions.
